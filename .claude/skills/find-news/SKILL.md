# find-news — сбор свежих новостей по QA-автоматизации (Claude Code / deep-search)

Скилл собирает свежие новости по автоматизации тестирования и смежному тулингу за последнюю неделю и отдаёт их строго по контракту `NewsItem[]`. Это **первое звено** цепочки `find-news → score-news → news-report`, но работает и автономно.

Все рассуждения и саммари — на русском. Заголовки новостей, названия инструментов и ссылки — **в оригинале** (не переводить и не транслитерировать названия продуктов).

> **Важно:** скилл выполняется **внутри Claude Code** и добывает новости его веб-инструментами (`WebSearch` + `WebFetch`) широким многозапросным проходом. Никакого «режима Research» из claude.ai здесь нет — см. раздел «Контекст запуска».

---

## Когда вызывается

- Пользователь набирает `/find-news` или `find-news`.
- Просит: «найди новости по автоматизации тестирования», «свежие релизы тулзов», «что нового в QA/SDET за неделю», «собери новости для дайджеста», «обзор свежих релизов фреймворков / CI».
- Из контекста ясно, что нужен сбор актуальных новостей по тематике канала — даже если слова «find-news» нет.

Если непонятно, нужен ли именно сбор новостей или что-то другое (например, разбор одной конкретной статьи), — уточни одной короткой репликой.

---

## Контекст запуска: Claude Code (deep-search)

Скилл работает **внутри Claude Code** и добывает новости его инструментами, а не «режимом Research» из claude.ai (в Claude Code такого тумблера нет). Глубину обеспечивает многозапросный проход:

- **WebSearch** — поиск, возвращает ссылки. Гоняй его **много раз** по разным инструментам и типам источников (см. «Как искать»). Это десятки запросов, а не один.
- **WebFetch** — открыть первоисточник (release notes, пост, страница релиза) и вытащить точную дату и суть, а не довольствоваться сниппетом.
- **Если установлен плагин/скилл deep-research или deep-search** (например, на базе Parallel, Firecrawl, Exa) — задействуй его для большего охвата и аккуратного скрейпинга. Встроенных `WebSearch` + `WebFetch` достаточно как базовый минимум.

**Почему так.** Качество дайджеста определяется широтой и свежестью охвата за неделю. Один запрос вернёт узкий срез и пропустит release notes, GitHub Releases и нишевые блоги — поэтому проход всегда широкий и многозапросный.

## Тематический охват (DOMAIN_SCOPE)

Берём новости по этим направлениям:

- **Фреймворки автотестов:** Playwright, Selenium / Selenide, Cypress, pytest, JUnit, TestNG, WebdriverIO, Robot Framework и др.
- **Отчётность и инфраструктура тестов:** Allure / Allure TestOps, тест-репортинг, тестовые стенды.
- **CI для тестов:** GitHub Actions, GitLab CI, Jenkins и пайплайны под автотесты, параллелизация (`pytest-xdist` и аналоги).
- **Контрактное тестирование:** Pact, схемы, swagger/OpenAPI-coverage, consumer-driven contracts.
- **AI в тестировании:** генерация тестов, self-healing локаторы, AI-ассистенты для QA, агенты для тест-дизайна.
- **Нагрузочное и перформанс:** k6, Gatling, JMeter, Locust.
- **Process-automation тулинг:** автоматизация разработки (dev-tooling, DevEx), автоматизация Agile- и бизнес-процессов, оркестраторы и no/low-code-автоматизации в контексте инженерных команд.

Если новость на стыке (например, релиз языка/рантайма, который заметно влияет на автотесты) — включать, но в `summary` явно показать связь с тестированием/автоматизацией.

Вне охвата: общие IT-новости без отношения к тестированию/автоматизации (продуктовые анонсы, не-инженерные темы, маркетинг).

---

## Окно свежести (RECENCY)

- Берём новости за **последнюю неделю** — последние 7 дней от текущей даты.
- Текущую дату бери из контекста запуска (не «зашивай» в скилл).
- `published_at` определяй по дате публикации/релиза, а не по дате индексации поисковиком.
- Если у материала **нет явной даты** или дата сомнительна — не включай (лучше пропустить, чем тянуть протухшее). Исключение: GitHub Release с явным тегом и датой.
- Граница включительная: ровно 7 дней назад — ещё берём.

## Источники: где искать

| Тип источника | Примеры |
|---|---|
| Официальные release notes / changelog | сайты и доки Playwright, Cypress, pytest, JUnit, Allure, k6, Gatling и т. п. |
| GitHub Releases | страницы `/releases` ключевых репозиториев инструментов |
| Блоги вендоров и команд | инженерные блоги мейнтейнеров и компаний-владельцев инструментов |
| Dev-сообщества | dev.to, Medium, Habr (теги по тестированию / QA / автоматизации) |
| Отраслевые рассылки / newsletters | QA- и testing-дайджесты, еженедельные подборки |
| Конференции и доклады | анонсы и материалы профильных конференций, свежие talks |
| QA/SDET-сообщества | Ministry of Testing и аналогичные площадки, тематические подборки |

Источники разнообразить: не тянуть весь топ из одного домена.

## Как искать (многозапросный план)

1. **Раскладка по осям.** Сгенерируй запросы по двум осям: (а) инструмент/тема из охвата, (б) тип источника, и прогоняй их через `WebSearch`. Примеры: «Playwright release», «pytest changelog», «Allure TestOps news», «Cypress GitHub release», «contract testing Pact news», «AI test generation», «k6 release notes», «Habr автотесты», «dev.to testing», «testing newsletter <месяц>».
2. **Свежесть в запросе.** Добавляй временной маркер («this week», «<месяц> <год>», «latest»), но не привязывайся к устаревшему году — используй текущую дату из контекста.
3. **Итерации.** После первой волны добей пробелы: темы из охвата, по которым ничего не нашлось, прогони ещё раз с другой формулировкой/источником.
4. **Открывай первоисточник через `WebFetch`.** Для значимых находок открывай саму страницу (release notes, пост), а не только сниппет, — оттуда бери точную дату и суть.
5. **Дедуп.** Убирай дубли по канонической ссылке и по нормализованному заголовку (один и тот же релиз с трёх агрегаторов — одна запись со ссылкой на первоисточник).
6. **Фильтр свежести.** Выкидывай всё за пределами окна RECENCY.

## Контракт выхода: `NewsItem[]`

Главный артефакт — **строгий JSON-массив** объектов `NewsItem`. Этот массив один-в-один уходит на вход скиллу `score-news`, поэтому структура фиксирована.

Поля `NewsItem`:

| Поле | Тип | Правила |
|---|---|---|
| `id` | string | Стабильный слаг: `kebab` из инструмента и сути, напр. `playwright-1-50-release`. Уникален в пределах выдачи. |
| `title` | string | Заголовок **в оригинале** (язык источника). Без перевода и транслитерации. |
| `url` | string | Канонический URL первоисточника. Без трекинговых хвостов. |
| `source` | string | Имя источника или домен: `playwright.dev`, `Habr`, `dev.to`, `GitHub`. |
| `published_at` | string | Дата в ISO: `YYYY-MM-DD` (если известно время — `YYYY-MM-DDTHH:MM` + зона). |
| `lang` | string | Язык материала: `en`, `ru`, … |
| `summary` | string | Суть в 1–2 предложениях **на русском**: что произошло и почему касается автоматизации/тестирования. Без оценок (оценка — задача `score-news`). |

Формат вывода — один fenced-блок ` ```json ` с массивом:

```json
[
  {
    "id": "playwright-1-50-release",
    "title": "Playwright 1.50 Released",
    "url": "https://playwright.dev/docs/release-notes",
    "source": "playwright.dev",
    "published_at": "2026-06-03",
    "lang": "en",
    "summary": "Вышел Playwright 1.50: улучшения trace viewer и новые опции запуска тестов. Напрямую влияет на e2e-автотесты на Playwright."
  }
]
```

Если за неделю ничего значимого не нашлось — отдай пустой массив `[]` и одной строкой поясни это в превью.

## Цитирование источников

- Сохраняй ссылки на источники, найденные через `WebSearch`/`WebFetch`.
- В `url` всегда первоисточник, а не агрегатор/пересказ.
- **Ничего не выдумывай.** Нет подтверждённой ссылки и даты — нет записи. Не «додумывай» версии и даты релизов.

---

## Превью для человека

После JSON-блока — короткое человекочитаемое превью (не часть контракта, для глаз):

- Одна строка статистики: «Рассмотрено кандидатов: N, после дедупа и фильтра свежести отобрано: M».
- Список отобранного: `— <Заголовок> — <source>, <дата>` (по одной строке на новость, без баллов).

Пример:

```
Рассмотрено кандидатов: 28, отобрано: 6.
— Playwright 1.50 Released — playwright.dev, 2026-06-03
— pytest 8.4 changelog — GitHub, 2026-06-02
…
```

---

## Чего не делать

- **Не одиночный запрос.** Глубина даётся многозапросным проходом через `WebSearch`/`WebFetch` (deep-search), а не одним поиском.
- **Не выдумывать** новости, версии, даты, ссылки.
- **Не тянуть протухшее** — всё строго в окне RECENCY.
- **Не дублировать** один релиз из нескольких агрегаторов.
- **Не оценивать и не ранжировать** — ни баллов, ни «топов». Это работа `score-news`.
- **Не переводить и не транслитерировать** названия инструментов и заголовки.
- **Не выходить за охват** — общие IT-новости без связи с тестированием/автоматизацией не берём.

---

## Принципы (theory of mind)

- **Широта важнее красоты.** Лучше прочесать на пять источников больше, чем дольше полировать саммари.
- **Первоисточник важнее агрегатора.** Релиз — со страницы релиза, а не с пересказа.
- **Свежесть — это честность.** Нет надёжной даты в окне — не включаем.
- **Скилл знает свою границу.** `find-news` только собирает. Оценка — `score-news`, отчёт — `news-report`. Не лезь в чужую зону.
