# news-report — Markdown-дайджест из оценённых новостей

Скилл превращает оценённый список `ScoredItem[]` в чистый Markdown-дайджест под Obsidian. Это **третье звено** цепочки `find-news → score-news → news-report`, но работает и автономно — оценённый список можно подать руками.

Работает внутри Claude Code. Сам Markdown скилл отдаёт в ответ; запись в файл (например, `News/<YYYY-MM-DD>.md` в репозитории) делает агент или Routine — см. план Routine.

Текст отчёта — на русском (`REPORT_LANG`). Заголовки новостей, названия инструментов и ссылки — **в оригинале**.

---

## Когда вызывается

- Пользователь набирает `/news-report` или `news-report`.
- Просит: «сделай отчёт по новостям», «собери дайджест», «дайджест за день/неделю», «оформи дайджест в Markdown», «свёрстай отчёт».
- На руках есть оценённый список (из `score-news` или вручную), который нужно оформить в отчёт.

---

## Вход: `ScoredItem[]`

Канонический вход — JSON-массив `ScoredItem` по общему контракту цепочки:

```
ScoredItem = NewsItem + { score, rationale, rank }
```

- **В цепочке** бери последний выданный блок `ScoredItem[]` (вывод `score-news`).
- **Автономно** принимай оценённый список, поданный пользователем. Если `rank` не проставлен — отсортируй сам по убыванию `score`.
- **Порядок.** Доверяй входящему порядку/`rank`; ничего не пересортировывай, кроме случая отсутствия `rank`.
- **Пустой вход** → короткий отчёт «значимого не найдено» (см. ниже).

### Необязательная мета прогона

Сверх строгого контракта скилл может принять из контекста (от Routine, от `find-news` или от пользователя):

- **дату отчёта** — иначе берётся текущая дата из контекста запуска;
- **«рассмотрено»** — сколько кандидатов просмотрел `find-news` до фильтра. Если число доступно — показываем «рассмотрено N · отобрано M»; если нет — только «отобрано M».

Меты в структурном контракте нет намеренно: так `news-report` остаётся автономным и стыкуется с любым источником `ScoredItem[]`.

---

## Параметры отчёта

- **TOP_N = 5** — сколько новостей попадает в секцию «Топ». Остальные уходят в «Остальное».
- **REPORT_LANG = русский** — язык подписей и текста; данные новостей не переводим.

---

## Структура отчёта

### Шапка

- H1-заголовок: `# Дайджест QA-автоматизации — <YYYY-MM-DD>`.
- Строка контекста: окно (`последняя неделя`) и краткий охват тем — перечисли инструменты/темы, реально встретившиеся в подборке (например, `Playwright, pytest, Allure, contract testing`); если подборка пёстрая — обобщи.
- Строка счётчиков: `Новостей: рассмотрено N · отобрано M` (или `Новостей: отобрано M`, если «рассмотрено» недоступно). `M` = длина входного массива.

### Секция «Топ-`TOP_N`»

`## Топ-5` (число = TOP_N). Берём первые `TOP_N` элементов по рангу. Для каждого:

- `### <rank>. [<title>](<url>) — <score>` — заголовок-ссылка с баллом.
- строка `**Источник:** <source> · **дата:** <published_at>`.
- `**Почему важно.** <rationale>` — обоснование из `ScoredItem`.
- абзац с сутью — `summary`.

### Секция «Остальное»

`## Остальное` — всё, что не вошло в топ, компактным списком по рангу:

- `- [<title>](<url>) — <score> · <source>, <published_at>` — по строке на новость.

Если новостей всего `≤ TOP_N` — все идут в «Топ», секцию «Остальное» опускаем.

---

## Правила Markdown (Obsidian)

- **Без HTML.** Только Markdown.
- **Заголовки** — `##` для секций, `###` для элементов топа; единственный `#` — заголовок дайджеста.
- **Ссылки** — только `[текст](url)`. **Без «голых» URL** в тексте. `source` — это имя/домен обычным текстом (не ссылка), напр. `playwright.dev`, `Habr`, `GitHub`.
- **Эмодзи** — не нужны; отчёт сухой и сканируемый.
- **Жирный** — только для коротких подписей-меток (`Источник`, `дата`, `Почему важно`), не злоупотреблять.
- **Типографика** — «ёлочки», длинное тире `—` с пробелами, средний дефис в диапазонах без пробелов.

---

## Пустой день / мало новостей

- **Пустой вход (`[]`)** — короткий отчёт:

```markdown
# Дайджест QA-автоматизации — 2026-06-07

**Окно:** последняя неделя

За неделю значимых новостей по автоматизации тестирования не найдено.
```

- **1–4 новости** — секция «Топ» с тем, что есть; «Остальное» опускаем.

## Чего не делать

- **Не выдумывать** новости, баллы, даты, ссылки. Верстаем только то, что во входе.
- **Не пересортировывать** — порядок задаёт `rank`/`score` из `score-news`.
- **Не менять** `title`, `summary`, `rationale` по смыслу. Допустима лишь лёгкая чистка пробелов/типографики.
- **Без HTML и без голых URL** — это сломает чистоту под Obsidian.
- **Не искать и не оценивать.** Поиск — `find-news`, оценка — `score-news`. `news-report` только верстает.
- **Не переводить** названия инструментов и заголовки.

---

## Принципы (theory of mind)

- **Дайджест для сканирования.** Читатель пробегает топ глазами: заголовок-ссылка, балл, одна строка «почему», суть. Ничего лишнего.
- **Чистый Markdown переживёт перенос.** Файл уедет в Obsidian (а позже — в слой публикации), поэтому без HTML и без хрупкого синтаксиса.
- **Отчёт честен к пустоте.** Нет новостей — так и пишем одной фразой, без воды и без выдуманных строк.
- **Скилл знает свою границу.** `news-report` только оформляет готовую оценку. Не добывает и не судит.
