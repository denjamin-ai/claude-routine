# score-news — оценка и ранжирование новостей (0–10)

Скилл принимает список новостей `NewsItem[]`, оценивает каждую по шкале **0–10 (шаг 0.1)** и отдаёт `ScoredItem[]`, отсортированный по убыванию балла. Это **второе звено** цепочки `find-news → score-news → news-report`, но работает и автономно — список можно подать руками.

Работает внутри Claude Code как звено цепочки. Оценка — это рассуждение модели над JSON: внешние инструменты и веб-поиск не нужны.

Все рассуждения и обоснования (`rationale`) — на русском. Заголовки и названия инструментов в данных не трогаем, оставляем как пришли.

---

## Когда вызывается

- Пользователь набирает `/score-news` или `score-news`.
- Просит: «оцени новости», «проскорь список», «оцени и отсортируй», «расставь баллы», «отранжируй дайджест».
- На руках есть список новостей (из `find-news` или вручную), который нужно оценить и упорядочить.

Если на входе явно не новости, а что-то другое, — уточни одной короткой репликой.

---

## Вход: `NewsItem[]`

Канонический вход — JSON-массив `NewsItem` по общему контракту цепочки:

```
NewsItem = { id, title, url, source, published_at, lang, summary }
```

- **В цепочке** бери последний выданный блок `NewsItem[]` (вывод `find-news`).
- **Автономно** принимай список, поданный пользователем, — хоть строгим JSON, хоть как разнородный список ссылок/заголовков. В этом случае сначала нормализуй вход в `NewsItem[]`: разнеси по полям то, что есть.
- **Пропуски полей.** Не выдумывай данные. Если поля нет (например, нет `published_at`), оцени по тому, что есть, занизь соответствующий критерий до нейтрального и отметь пробел в `rationale`.
- **Пустой вход.** Если массив пустой — верни `[]` и поясни одной строкой в превью.

## Система оценки (0–10, шаг 0.1)

Итоговый балл — взвешенная сумма пяти критериев. Каждый критерий оценивается по 0–10, затем складывается с весом.

### Критерии и веса

| Критерий | Обозн. | Вес | Что меряет |
|---|---|---|---|
| Релевантность тематике канала | R | **0.30** | Насколько новость попадает в DOMAIN_SCOPE канала (автоматизация тестирования и смежный тулинг). |
| Практическая польза для SDET/QA | P | **0.25** | Можно ли это применить в работе тестировщика/SDET. |
| Новизна | N | **0.20** | Насколько это значимо и ново, а не рутинный патч. |
| Авторитетность источника | A | **0.15** | Первоисточник/вендор против анонимного пересказа. |
| Свежесть | F | **0.10** | Тонкая настройка внутри недельного окна. |

Сумма весов = **1.00**.

### Шкалы по критериям (опорные точки)

**R — Релевантность (вес 0.30)**
- 9–10 — ядро тематики: автотест-фреймворк, CI для тестов, контрактное/нагрузочное тестирование, AI-в-тестировании, QA/SDET-тулинг.
- 6–8 — смежное с явной связью: релиз языка/рантайма/CI/инструмента, влияющий на тесты; process-automation для инженерных команд.
- 3–5 — связь косвенная, её надо притягивать.
- 0–2 — вне тематики канала.

**P — Практическая польза для SDET/QA (вес 0.25)**
- 9–10 — можно внедрить сразу: новая фича/инструмент/приём, меняющий рабочий процесс.
- 6–8 — полезный паттерн/исследование, применимо с доработкой.
- 3–5 — интересно, но без прямого выхлопа (обзор/мнение).
- 0–2 — анонс без практической ценности.

**N — Новизна (вес 0.20)**
- 9–10 — мажорный релиз, новый инструмент, заметный сдвиг подхода.
- 6–8 — заметный минорный релиз с новыми фичами / свежий приём.
- 3–5 — рутинный патч, переупаковка известного.
- 0–2 — косметика, повтор уже известного.

**A — Авторитетность источника (вес 0.15)**
- 9–10 — официальный первоисточник: release notes, репозиторий, блог вендора/мейнтейнера.
- 6–8 — уважаемое сообщество / известный автор, профильная рассылка.
- 3–5 — обычный блог / Medium / dev.to без явной репутации.
- 0–2 — аноним / сомнительный агрегатор.

**F — Свежесть (вес 0.10)**
- 9–10 — 0–2 дня от текущей даты.
- 6–8 — 3–4 дня.
- 3–5 — 5–7 дней.
- 0–2 — вне недельного окна (просочилось мимо фильтра; отметить в `rationale`).

### Итоговый балл

```
score = round( 0.30·R + 0.25·P + 0.20·N + 0.15·A + 0.10·F , 1 )
```

- Округление до **0.1** (half up). Результат зажимается в диапазон **[0, 10]**.
- Критерии — внутренняя кухня скилла. В JSON выводится только итоговый `score`; разбор по критериям в контракт не попадает (см. «Выход»). Решающие факторы коротко отражай в `rationale`.

### Тай-брейк

При равенстве итогового `score` упорядочивай по очереди:

1. выше **P** (практическая польза);
2. затем выше **R** (релевантность);
3. затем выше **N** (новизна);
4. затем свежее (меньше дней с публикации);
5. затем авторитетнее источник (выше **A**);
6. если всё ещё равно — по алфавиту `title` (для детерминизма).

## Выход: `ScoredItem[]`

Строгий JSON-массив `ScoredItem`, **отсортированный по убыванию `score`** (с учётом тай-брейка). Контракт:

```
ScoredItem = NewsItem + { score, rationale, rank }
```

То есть все поля `NewsItem` сохраняются как есть, плюс добавляются три:

| Поле | Тип | Правила |
|---|---|---|
| `score` | number | Итоговый балл 0–10, шаг 0.1. |
| `rationale` | string | 1–2 предложения **на русском**: что подняло и что опустило балл. Не пересказ `summary`, а объяснение оценки. |
| `rank` | number | Позиция в отсортированном списке, начиная с 1. |

Формат вывода — один fenced-блок ` ```json ` с массивом:

```json
[
  {
    "id": "playwright-1-50-release",
    "title": "Playwright 1.50 Released",
    "url": "https://playwright.dev/docs/release-notes",
    "source": "playwright.dev",
    "published_at": "2026-06-03",
    "lang": "en",
    "summary": "Вышел Playwright 1.50: улучшения trace viewer и новые опции запуска тестов. Напрямую влияет на e2e-автотесты на Playwright.",
    "score": 8.6,
    "rationale": "Мажорный релиз ядрового для канала фреймворка от первоисточника, фичи применимы сразу; балл чуть снижает инкрементальность изменений.",
    "rank": 1
  }
]
```

Пустой вход → пустой массив `[]`.

## Превью для человека

После JSON-блока — короткое превью (не часть контракта, для глаз): по одной строке на новость в порядке ранга.

```
1. 8.6 — Playwright 1.50 Released (playwright.dev, 2026-06-03)
2. 7.9 — pytest 8.4 changelog (GitHub, 2026-06-02)
…
```

Если нужно — по запросу можно показать разбор по критериям (`R / P / N / A / F`) отдельной таблицей, но в JSON-контракт он не идёт.

---

## Чего не делать

- **Не менять данные новости.** `title`, `url`, `summary` и прочие поля `NewsItem` переносятся без правок.
- **Не выдумывать** недостающие поля и факты. Нет данных — занижай критерий и пиши об этом в `rationale`.
- **Не добавлять лишние поля** в JSON. Контракт строгий: только `NewsItem` + `score` + `rationale` + `rank`.
- **Не сортировать по чему-либо, кроме `score`** (+ тай-брейк). Порядок выдачи = порядок рангов.
- **Не собирать новости.** Поиск — задача `find-news`. Отчёт — задача `news-report`.
- **Не переводить и не транслитерировать** названия и заголовки.

---

## Принципы (theory of mind)

- **Польза и релевантность — главные оси.** Самые тяжёлые веса не случайны: канал технический, читателю нужно применимое и по теме.
- **Свежесть — это тонкая настройка, а не главный приз.** Всё уже в недельном окне; свежесть лишь разводит близкие баллы.
- **Обоснование объясняет балл, а не пересказывает новость.** В `rationale` — почему столько, а не что произошло.
- **Детерминизм.** Одинаковый вход → одинаковый порядок. Для этого и нужен полный тай-брейк вплоть до алфавита.
- **Скилл знает свою границу.** `score-news` только оценивает и ранжирует. Не ищет и не верстает отчёт.
